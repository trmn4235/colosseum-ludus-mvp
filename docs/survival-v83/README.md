# Survival V83

Singleplayer now contains 4x5, Solo 20 and Survival. The Survival card uses the supplied poster unchanged. Preparation displays the global best stage, ludus, gladiator and class, also shown for the first five active seconds inside the arena. After that initial preparation, Stage 1 spawns one enemy. Every cleared wave starts the next immediately. Stage N spawns `N % 10 === 0 ? N / 10 : 1` enemies: 10=1, 20=2, 40=4, 41=1, 60=6, 100=10, 101=1. There is no list of special stages and no 19-enemy limit. All enemies share the opposing team and target the lone player.

Player health, stamina, equipment and body injuries persist across waves. Only active waves are simulated; up to eight recently defeated models finish their fall for 1.8 seconds, then release their instance resources. The top centre shows faint previous/next stages around the larger current stage. Death ends the run and the result lists reached and completed stages separately. The record uses reached stage, with completed stage as tie-breaker.

The existing authenticated battle entry checks, equipment ownership, request deduplication, exercise energy and recovery rules remain in use. Survival has no new economy rewards, doesn't increment normal wins/losses or daily match categories, and preserves carried equipment after death or withdrawal. Actual battle results use the existing durable, owner-specific outbox and receipts. The global record stores labels from the server-owned account and gladiator snapshot. Private tables deny direct client access; only the authenticated record RPC is exposed. Settlement validates the stage/kill totals, duration and ticket ownership. Like existing PvE, combat itself remains client simulated; this is not an authoritative anti-cheat server.

Apply `supabase/migrations/20261012033047_survival_v83.sql` before publishing the client. It extends the existing start/finish functions without replacing unrelated logic and can be applied repeatedly. Battle records remain compatible with the existing resume/abandon controls. As in the existing arena, reload of an unfinished battle restarts its simulation; only settled runs count as records.

Validation: `LUDUS_PGLITE_MODULE=/path/to/@electric-sql/pglite node tests/survival-v83.cjs` executes the shipped combat engine and real PostgreSQL functions. It covers the first five seconds, 310 sequential waves, multi-opponent targeting, partial clears, retained player state, death, normal-mode wins, migration retries, owned equipment, cross-account denial, replayed receipts, snapshot labels, permissions and withdrawal. Existing combat, bot-defense and result tests also pass. Browser visual QA and physical-phone performance were not available in this session.
