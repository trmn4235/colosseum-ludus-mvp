# V284 — Papirüsle gelişen özel çalışanlar

Six distinct stationed specialists: Doctore beside training equipment, cook beside the dining cauldron, doctor in the infirmary, smith beside the anvil, guard beside the Rome exit, groom replacing the existing stable attendant. Each uses a different skin tone, hair colour, hair style and beard style, with a profession-specific tunic colour. Existing MakeHuman source is downloaded once; stationary visible meshes are baked once, cached and frustum culled, without live staff skeleton animation.

The user cancelled all six earlier skill lists and explicitly chose to determine new bonuses separately. This release deliberately seeds no old skills, replacement bonuses, lesson catalogue or loot rate. Real profiles therefore start at 0 overall and 0/500. The 26/500 and 0.03% examples appear only in test fixtures. Battle drop activation and effect consumers must accompany the subsequently agreed catalogue; percentages are not claimed to affect live combat yet.

Private server tables and authenticated owner-only RPCs support 500 unique lessons per role. Receiving a lesson contributes to the collection, not overall. Explicitly reading an owned, unread, configured lesson increases overall by 0.2, up to 100; passive totals derive from learned lessons. UUID receipts and account locks prevent duplicate reading on retries. Clients cannot grant papyri or write progress. Profiles separate collection, read and unread counts and list learned percentages, retaining 0.03% precision. There is no work/time/XP route to staff growth.

Daily kitchen portions now count gladiators, the eight existing caravan workers (including lazily initialized roster records and workers away), and six specialists. Existing stock, serving receipts, revision conflicts, purchases and day boundaries are preserved. State reads do not consume inventory. The menu shows the category breakdown and total people.

Validation: PGlite owner/anonymous isolation, cancelled empty catalogue, collection versus learning, cap, percent precision, duplicate reading, receipt replay, food counts, atomic stock consumption and replay. Existing V265 kitchen regression retained. Full Ludus/browser tests run in GitHub CI, including six NPCs, collision bounds, profile selection, failed-response retry, nine theme/viewport combinations and kitchen breakdown. Managed preview browser has WebGL disabled, so local CUA checks cover profile DOM, themes, reading flow and layout; CI checks the real rendered models.
